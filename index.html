F1TENTH Autonomous Racing Platform

A complete autonomy stack running on a 1/10-scale autonomous race car, built on a Jetson AGX Orin with ROS2 Humble, a ZED Mini stereo camera, and a VESC motor controller.

What I built

  • Dual-EKF localization stack using robot_localization fusing wheel odometry, IMU, and lidar based particle filter.
  • MPPI controller for trajectory following and obstacle avoidance.
  • Deployed Reinforcement Learning policies for autonomous racing with online adaptation module that collects data and sends it to an ofline server for the policy to improve on and recive the new weights
  • Sim-to-real PPO policy transfer using a frame-skip curriculum and direction randomization during training.
  • foxglave_visualization, a ROS2 companion package for the mapping and post-processing workflow.

Notable problem solved

The VESC driver publishes odometry with a zero covariance matrix, which silently breaks EKF fusion. I wrote odom_cov_fixer.py to inject realistic covariance values before the message reaches the filter.

Crazyflie KNODE Tube Flight

Flying a Crazyflie nano-quadrotor through a physical tube, where aerodynamic ground and wall effects make the nominal dynamics model badly wrong. Tracked with OptiTrack motion capture.

Approach

  • A geometric controller as the baseline, augmented with L1 adaptive control for fast disturbance rejection.
  • A KNODE (Knowledge-based Neural ODE) residual model learning the gap between nominal and true dynamics, with residuals expressed in the body frame.
  • A 400 Hz buffered CSV logging pipeline, gated on tube-pass state so training data captures only the relevant flight regime.
  • Two KNODE variants for comparison: radial-distance-only inputs versus full pose and attitude inputs.

Key insight

The correct training input is the pre-gamma desired thrust and torque, not the commanded thrust. Using the commanded value causes KNODE to learn the boundary correction term instead of the true aerodynamic residual, which defeats the purpose of the model.

Trajectory Optimization:Humanoid Backflip

A nonlinear model predictive controller for quadrotor flight, formulated directly on the quaternion state to avoid the gimbal and wrapping problems that come with Euler angle formulations.

Formulation

  • 10-state full quaternion model with RK4 integration across the prediction horizon.
  • Soft tube constraints, so the solver stays feasible when the reference is briefly unreachable rather than failing outright.
  • Baumgarte stabilization to keep the quaternion on the unit sphere across integration steps instead of drifting off it.

Solver strategy

acados with SQP-RTI is the deployment target, chosen for real-time solve rates on embedded hardware. ipopt is used only offline to validate that the RTI solution matches the fully converged one.

Roof-Mounted Radar Enclosure

A protective radome for a roof-mounted radar unit. The design problem is a tradeoff: the enclosure has to survive weather and mounting loads while staying as close to RF-transparent as possible.

Design considerations

  • Material selection between polycarbonate and HDPE tubing, weighing dielectric constant and loss tangent against structural durability and UV resistance.
  • Wall thickness tuned to the operating wavelength, since a poorly chosen thickness causes reflection losses that directly degrade detection range.
  • Frequency-dependent sizing, with the target band determining how tight the thickness tolerance needs to be.
